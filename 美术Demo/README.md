## 启动

Windows x64，.NET Framework 4.8；无需管理员权限、API Key 或外部图像服务。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\美术Demo\launch-demo.ps1
```

构建后直接双击 `美术Demo/runtime-desktop/桌面修仙-透明桌面Demo.exe`。必须保留旁边 Assets、ArtDemoAssets 目录；默认隔离修士保存在同目录 `profiles/player`，退出后继续同一修士。此目录不是正式存档。

普通入口默认 **Observe（只读观察）**：观察本用户符合规则的临时文件与内存压力，生成标明来源的桌面妖物。新私有档的三项维护授权均关闭；观察与战斗本身不会授权删除文件、整理内存或关闭程序。授权属于当前私有档，重启后加载该档已保存的选择。

便携交付为 `桌面修仙-透明桌面Demo.zip`，完整解压后双击同名 EXE。包内不附带验收档或真实桌面原始录屏。最新画面与回归见 `qa/ecology-20261022/`，当前结论和未完成范围见 [电脑生态实施与验收记录](电脑生态实施与验收记录-20261022.md)。

## 桌面操作

1. 新凡人首开会显示可收起的修行手札。未选中的普通妖物只巡游，不会趁阅读说明围攻；凡人未选敌时不会自行跑开，仍可拖动移动。点击桌面妖物选敌，修士会接近；进入射程后再次点击出一招。凡人每招需玩家操作，点击另一只会立即切换当前目标。
2. 敌人临近出手时，修士头顶提示「即将受击 · 点修士格挡」。点击修士格挡，手札记录实际挡下与承受伤害，冷却沿用正式规则。拖动修士移动，拖动不会触发格挡。右键修士/妖物或点击托盘图标打开修行操作。
3. 十次有效击杀后，在修行面板主动点击「灵根觉醒」。实际修仙状态进入炼气，外观同步切换，自动作战默认开启。
4. 关闭/最小化功能面板只收起界面，桌面角色继续活动、自动战斗与修炼。托盘可隐藏/恢复演员；隐藏也不停止修为增长。
5. 手札「修行与洞天」中可改修已有功法、打开百业、破境、灵域、洞天；「行囊与设置」显示当前兵器、已有数量和下件兵器所需历练，选择已有兵器后可查看独立原画与真实属性，点击对应的「装备」按钮立即生效并保存。获得新兵器不会打断正在浏览的选择。百业仍默认关闭，只有玩家在道碑内明确选择后才开始识别。
6. 托盘或修行面板点击「保存并退出」。保存失败会明确提示，正常交互退出暂不执行，以保留本次进度。

没有全局强制快捷键，没有开机自启注册。仅用户主动打开的功能面板会获得焦点，角色与妖物窗口本身不激活其他应用。

## 电脑生态与真实维护

在托盘或修行手札打开「电脑生态与维护」，查看妖物来源与实际维护记录。普通妖物对应符合复核规则的本用户 Temp 文件，内存 Boss 对应内存压力；没有授权时击杀只结算修行奖励。自动战斗解锁不代表同意自动维护。

三项维护开关各自独立，并在开启前说明范围：

- **文件清理授权**：击败绑定文件怪后，才处理本用户 Temp 中超过 24 小时且通过复核的文件；占用、发生变化或不符规则的文件跳过。
- **内存维护授权**：击败对应 Boss 后，尝试整理部分同会话后台程序工作集；不结束进程，不保证性能提升。
- **无人值守维护授权**：只允许自动战斗调用已经分别授权的文件或内存维护，不授予新的处理范围，不授权关闭程序。各项均可随时关闭。

只开启文件或内存维护、未开启无人值守维护时，自动作战仍可击败这些来源的妖物并获得修行奖励；该次自动战斗不会执行真实维护。撤销无人值守维护后，自动作战仍继续。

「查看可正常退出的后台程序」只观察可核实的候选；程序不等于垃圾，由玩家选择单个程序生成程灵。击败后仍须当次确认程序名称、PID 与路径，才请求**正常退出**。每次确认只针对该目标，不保存为长期授权；不自动选程序、不自动退出程序、不强制结束，也不支持无正常窗口退出方式的进程。程序可能弹出保存提示；拒绝、取消、超时或身份变化如实记录，不按成功处理。

实际结果写入当前私有档 `maintenance-results-v1.log`。磁盘记录以实际删除文件和字节为准；内存工作集变化与磁盘清理量分开，修为奖励不会换算成清理量。收起面板后仍可修行，维护权限仍由各独立开关控制。

## 独立测试档

```powershell
# 名称须全新；同名已有档不会被测试种子覆盖。
powershell -NoProfile -ExecutionPolicy Bypass -File .\美术Demo\launch-demo.ps1 -Profile verify-qishi-manual -Seed qishi-full
powershell -NoProfile -ExecutionPolicy Bypass -File .\美术Demo\launch-demo.ps1 -Profile verify-zhuji-manual -Seed zhuji
```

种子明确标注为测试档，预置境界、机缘或设施材料，用来验证既有突破与设施链路，不代表自然养成成果。带 `--seed` 的测试档、冒烟测试及桌面玩法自动验收均为 **Virtual（虚拟历练）**，不进行真实系统观察或维护；即使档内存在旧授权，也不能突破此限制。

正常游玩没有验收快进。桌面玩法自动验收默认使用 ×6 时间，仅加速流逝，不减少十杀要求、不注入战斗 HP 或奖励；显式 `--normal-speed` 验收为正常速率，仍为 Virtual。只读生态的原生桌面验收由单独工具执行，不开启维护授权。

## 美术与隔离

凡人身份采用已确认的 mortal-M2-polish-v2，炼气/筑基选用同人A组。新资源全部位于 `源代码/ArtDemoAssets`；原 Assets 保留。三阶段新增4×3图集、11独立部件+完整参考以及 .rects / .anchors，复用原有步态与IK实现必要的走路、攻击、格挡和调息表现。

五份业务存档及维护授权路径全部显式指向本 Demo 私有目录；正常游玩不读取或写入正式用户档、正式授权和其他长测档。显式自动验收仅只读真实档哈希以核对未改变。普通入口可以只读观察电脑来源，真实维护必须经过上述独立授权；Virtual 测试入口始终禁止真实观察及维护。网络探测保持关闭。主分支与正式 EXE 不参与打包覆盖。

提示词、高清源图、A/B 候选继续保留在 prompts/、generated/ 与生成来源 JSON；原 27 张新美术 PNG 全部保留，新增四种兵器资源后共 **31 张 PNG（28 张独立插画＋3 张角色分件图集）**。素材处理规则见 asset-inputs.json，分件生成工具见 tools/prepare-hero-rigs.py。

打包工具先按受控 `asset-manifest.json` 的文件名与 SHA-256 核对 28 张插画，再核对三阶段图集和各自 `.rects` / `.anchors`；runtime 的完整新美术文件集合及每个文件必须与源码一致。旧运行目录、缺图、额外文件或字节不一致均拒绝打包。ZIP 不包含任何 profiles、维护授权或原始桌面截图／录像。

## 预览与验收

原带场景窗口保留为开发预览，通过 `launch-art-preview.ps1` 显式启动，不作为正式桌面入口。

自动验收需要允许本 Demo 对自己的角色、妖物和面板执行鼠标点击，并保留可见桌面。只在新输出目录和 accept- / verify- 私有测试档执行：

```powershell
& .\美术Demo\runtime-desktop\桌面修仙-透明桌面Demo.exe --desktop-demo-accept .\美术Demo\qa\desktop-accept-new --profile accept-new
# 正常速率新玩家流程：20秒无输入阅读、真实换目标、较慢的主动出招、自然调息。
& .\美术Demo\runtime-desktop\桌面修仙-透明桌面Demo.exe --desktop-demo-accept .\美术Demo\qa\desktop-accept-normal-new --profile accept-normal-new --normal-speed
```

真实桌面结果、录像、存档与性能记录见本目录交付验收记录。离屏动作图只能作为美术证据，不能代替桌面玩法验收；中途遮挡、关闭或空白画面不得写成通过。短时通过不等于 8 小时自然养成通过；自然突破、按真实小时成熟的洞天作物、保存重载和资源趋势须以该次长测实际结果为准。
