# 《桌面修仙传》电脑生态与持续游玩 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让真实电脑负担、桌面妖物、获准维护、实际结果与修士成长形成可持续游玩的单机闭环。

**Architecture:** 复用 AdventureController、现有分层窗口、清理与内存维护管线以及五份业务存档。将“私有存档位置”与“是否允许观察或维护真实电脑”拆成独立决策，只增补小范围接入；保持一个业务状态源。进程治理为新增的独立能力，跨机仙界为后续独立项目。

**Tech Stack:** Windows x64、C#、.NET Framework 4.8、WinForms、UpdateLayeredWindow；现有 PNG / .rects / .anchors 美术资源。

**Spec:** 本轮用户已确认的产品构想与分步计划请求；仓库依据为 `设计/V6.0-持续修仙桌宠-开发基线.md`、`美术Demo/可玩性整改记录-20261022.md`。旧文档中的候选待定、层数和历史验收描述不能覆盖后续产品决定与当前代码。

## Global Constraints

- 不修改 main，不覆盖原版 Assets、正式 EXE、真实用户存档或既有长测环境。
- 正式入口默认透明桌面；人物与妖物使用小型独立透明窗口，无全屏覆盖层。
- 修行状态只来自现有正式业务，不建立第二套成长或战斗控制器。
- 新版构建与验证先输出到 `美术Demo/verification/eco-build/`，通过验收后才更新隔离运行包，并保留前版。
- 私有档只写当前独立 profile；授权也只写该 profile，不能继承正式用户授权。
- 自动战斗不等于自动维护；清文件、整理内存、无人值守维护维持独立授权。
- 游戏奖励与真实文件字节、内存观测、程序退出结果分开，不虚构性能收益。
- 无垃圾也可以持续修行；正常软件活动进入百业与灵域，不因软件正在运行就把它认定为垃圾。
- 自动化测试只操作明确创建的文件与进程夹具；不会把当前电脑全部候选作为清理测试对象。
- 原有隔离验收保持纯虚拟默认，不允许种子档、倍率或验收参数升级成真实维护权限。
- 本轮计划不视为已启用任何维护，也不包含无人值守结束进程或联网控制他人电脑。

## Review Focus

1. 增加电脑生态后，旧验收或存档迁移意外继承维护权限：步骤1、3、4覆盖默认、迁移和拒绝升级测试。
2. 扫描后文件或进程身份变化，战斗结算处理了另一个对象：步骤2、3、4覆盖变化、退出和 PID 复用。
3. 授权撤销、保存失败、部分成功或超时仍显示成功：步骤3、4覆盖取消、实测与持久化失败。
4. 游戏成长、洞天产出因为重复事件或重启重复结算：步骤5覆盖奖励幂等及跨档重放。
5. 桌面透明区域拦鼠标、抢焦点或后台占用持续增长：步骤6、7覆盖真实桌面与长时间样本。

## 步骤1：把私有存档与电脑观察／维护能力分开

**交付：** 同一个透明桌面入口支持纯虚拟、只读生态、可申请维护三种能力；未授权时零真实维护。新版普通入口默认只读生态，旧自动验收／冒烟入口强制纯虚拟。

**Files:** Create `源代码/DesktopEnvironmentPolicy.cs`、`美术Demo/tools/DesktopEnvironmentTests.cs`、`美术Demo/tools/verify-desktop-ecology.ps1`；Modify `源代码/DesktopDemoSession.cs`、`源代码/DesktopDemoState.cs`、`源代码/AdventureController.cs`、`美术Demo/launch-demo.ps1`。

**Interfaces:** 新增 `DesktopEnvironmentMode { Virtual, Observe, Maintain }` 与 `DesktopMaintenanceScope { FileCleanup, MemoryReclaim }`；`DesktopEnvironmentPolicy` 提供 `bool MayObserve` 和 `bool MayMaintain(DesktopMaintenanceScope scope, bool scopeConsent, bool automatic, bool automaticConsent)`。档案路径继续由 `DesktopDemoSession.ProfilePath(string name)` 负责，不能因环境模式而改变。Mode由入口约束与当前profile有效授权派生，不另存第二份授权事实：手札内逐项授权持久化成功后显示Maintain，全部撤销后回Observe；重启只恢复该profile有效授权，Virtual入口不能升级。MayMaintain先拒绝Virtual，再检查本次作用范围和自动维护门禁，不能只凭Maintain标签放行。用户无需使用命令行来申请维护。

- [x] 用实际控制器增加失败用例：Observe 可以读取但不能写系统；Maintain 没有相应授权也不能维护；Virtual 不启动监测或任务；私有 profile 仍全部隔离。
- [x] 用例还须证明 `--desktop-demo-accept`、`--desktop-demo-smoke`、`--seed` 和 `--normal-speed` 不能打开真实维护，异常策略值被拒绝；保存与重启不能扩大权限。

## 步骤4：建立真正的进程怪，先交付受控正常退出

**交付：** 可查看妖物绑定的具体程序与进程身份；玩家明确选择并确认后，击败目标可以请求对应程序正常退出。仅内存占用较高不能被认定为“多余”。

**建议的首版处置规则：** 精确身份为 PID、启动时间、可执行文件路径；只处理允许检查的同用户会话程序，跳过自身、系统／关键、前台、身份无法核实的对象。执行前再次核对身份与前台状态。第一版逐次确认、不持久化为全局结束授权，不支持无人值守关闭。没有正常退出入口、用户取消保存提示、超时或目标已变化时如实结束本次处理。强制结束进程另列子方案，不能偷偷用强杀补足“成功率”。这是本计划的建议边界，不代表已经实现进程治理。

**Files:** Create `源代码/DesktopProcessTargets.cs`、`源代码/DesktopProcessActions.cs`、`美术Demo/tools/DesktopProcessTests.cs` 及自有进程夹具；Modify `源代码/AdventureModel.cs`、`源代码/DesktopPlayerView.cs`、`源代码/DesktopPracticePanel.cs`、`源代码/AdventureController.cs`。

**Interfaces:** `ProcessIdentity` 包含上述三项身份；`ProcessCloseResult` 区分实际退出、仍运行、拒绝、取消、身份变化与错误。本步骤给DesktopMaintenanceScope增加ProcessExit，scopeConsent仅来自本次目标的单次确认，不复用文件／内存授权，也不要求先开启它们。`DesktopProcessActions.RequestGracefulClose(ProcessIdentity expected, CancellationToken token)` 只能在非Virtual入口、对应本次用户确认且身份复核通过后调用；自动调用始终拒绝。现有文件／内存授权不能授权此动作。

- [x] 先用夹具验证：PID复用、目标提前退出、启动时间／路径变化、突然变成前台、权限不足、无法识别、系统／关键目标全部拒绝或跳过；文件清理授权不能打开进程动作。
- [x] 做本地只读候选与详情，再接入受控的程序退出请求；只读观察和执行动作分开。
- [x] 将选择、战斗与退出结果接回同一业务状态；不得按怪物死亡就显示程序已结束，也不得重复执行一次确认。
- [ ] 用本项目启动的有保存提示和无提示进程夹具验证正常退出、用户取消、超时、撤销；测试不能关闭其他正在使用的程序。
- [x] 运行验证脚本 `-Suite Processes`，真实桌面录像能核实对应夹具程序状态后独立提交，并列出不支持的程序类型。

**里程碑 B：** 电脑负担有真实来历，文件／内存／进程各有准确动作与结果；同一修士继续成长。
