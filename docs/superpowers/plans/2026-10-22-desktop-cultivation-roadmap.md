# 《桌面修仙传》电脑生态与持续游玩 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让真实电脑负担、桌面妖物、获准维护、实际结果与修士成长形成可持续游玩的单机闭环。

## Global Constraints

- 不修改 main，不覆盖原版 Assets、正式 EXE、真实用户存档或既有长测环境。
- 正式入口默认透明桌面；人物与妖物使用小型独立透明窗口，无全屏覆盖层。
- 修行状态只来自现有正式业务，不建立第二套成长或战斗控制器。
- 新版构建与验证先输出到 `美术Demo/verification/eco-build/`，通过验收后才更新隔离运行包，并保留前版。
- 私有档只写当前独立 profile；授权也只写该 profile，不能继承正式用户授权。
- 自动战斗不等于自动维护；清文件、整理内存、无人值守维护维持独立授权。
- 游戏奖励与真实文件字节、内存观测、程序退出结果分开，不虚构性能收益。
- 无垃圾也可以持续修行；正常软件活动进入百业与灵域，不因软件正在运行就把它认定为垃圾。
- 自动化测试只操作明确创建的文件与进程夹具；不会把当前电脑全部候选作为清理测试对象。
- 原有隔离验收保持纯虚拟默认，不允许种子档、倍率或验收参数升级成真实维护权限。
- 本轮计划不视为已启用任何维护，也不包含无人值守结束进程或联网控制他人电脑。

## Review Focus

1. 增加电脑生态后，旧验收或存档迁移意外继承维护权限：步骤1、3、4覆盖默认、迁移和拒绝升级测试。
2. 扫描后文件或进程身份变化，战斗结算处理了另一个对象：步骤2、3、4覆盖变化、退出和 PID 复用。
3. 授权撤销、保存失败、部分成功或超时仍显示成功：步骤3、4覆盖取消、实测与持久化失败。
4. 游戏成长、洞天产出因为重复事件或重启重复结算：步骤5覆盖奖励幂等及跨档重放。
5. 桌面透明区域拦鼠标、抢焦点或后台占用持续增长：步骤6、7覆盖真实桌面与长时间样本。

## 步骤1：把私有存档与电脑观察／维护能力分开

**交付：** 同一个透明桌面入口支持纯虚拟、只读生态、可申请维护三种能力；未授权时零真实维护。新版普通入口默认只读生态，旧自动验收／冒烟入口强制纯虚拟。

**Files:** Create `源代码/DesktopEnvironmentPolicy.cs`、`美术Demo/tools/DesktopEnvironmentTests.cs`、`美术Demo/tools/verify-desktop-ecology.ps1`；Modify `源代码/DesktopDemoSession.cs`、`源代码/DesktopDemoState.cs`、`源代码/AdventureController.cs`、`美术Demo/launch-demo.ps1`。

**Interfaces:** 新增 `DesktopEnvironmentMode { Virtual, Observe, Maintain }` 与 `DesktopMaintenanceScope { FileCleanup, MemoryReclaim }`；`DesktopEnvironmentPolicy` 提供 `bool MayObserve` 和 `bool MayMaintain(DesktopMaintenanceScope scope, bool scopeConsent, bool automatic, bool automaticConsent)`。档案路径继续由 `DesktopDemoSession.ProfilePath(string name)` 负责，不能因环境模式而改变。Mode由入口约束与当前profile有效授权派生，不另存第二份授权事实：手札内逐项授权持久化成功后显示Maintain，全部撤销后回Observe；重启只恢复该profile有效授权，Virtual入口不能升级。MayMaintain先拒绝Virtual，再检查本次作用范围和自动维护门禁，不能只凭Maintain标签放行。用户无需使用命令行来申请维护。

## 步骤4：建立真正的进程怪，先交付受控正常退出
