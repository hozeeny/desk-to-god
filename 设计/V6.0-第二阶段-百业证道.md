# 《桌面修仙传》V6.0 第二阶段 · 百业证道（第一版）

分支：`feature/v6-baiye-cultivation`（基于 PR #1 最新提交 `97deed2`，独立 worktree 与构建输出目录开发；第一阶段长测程序、存档与采样环境全程未受影响）。

## 一、本阶段交付内容

「百业证道」第一版可运行闭环：开启功能并确认说明 → 识别或手动选择活动 → 有效时段积累道韵 → 百业道碑实时更新 → 满足条件触发第一条多道共鸣机缘。

核心理念：现实中的工作、学习、创作与娱乐，形成游戏里的后天道途。它是现有修仙成长体系的扩展，灵根、境界、功法与挂机修炼保持独立、互不影响。

### 1. 百业活动识别（八条道途）

| 现实活动 | 道途 | 自动识别示例（进程名） |
| --- | --- | --- |
| PPT 与演示制作 | 画境道 | powerpnt、wpp |
| 文案与文字创作 | 文道 | winword、wps、typora、obsidian 等 |
| 浏览器活动 | 游历道 | chrome、msedge、firefox 等（支持玩家主动选择具体活动） |
| 编程开发 | 阵道 | devenv、code、cursor、idea64、各 JetBrains IDE 等 |
| AI 工具使用 | 天机道 | chatgpt、claude、kimi、doubao、lmstudio 等 |
| 3D 建模与 CAD | 器道 | blender、3dsmax、maya、acad、sldworks 等 |
| 视频剪辑与创作 | 光影道 | premiere、resolve、afterfx、jianyingpro、capcut 等 |
| 电脑游戏 | 战道 | steam、wegame、leagueclient、dota2、cs2 等 |

- 优先本地前台应用类别识别；无法可靠判断（未知进程）时不产生收益，交由手动标记兜底。
- **隐私红线**：识别只读取前台窗口所属进程的进程名，永不读取文档正文、代码内容、聊天内容、网页历史或屏幕画面；道韵记录中只保存道途与来源类别，不保存应用名。
- 游历道提供手动具体活动选择（网上查阅资料 / 在线课程学习 / 影音娱乐 / 社区交流）。

### 2. 道韵成长

- 每种道途独立熟练度（道韵）与等级：初窥门径 → 小有所成 → 融会贯通 → 炉火纯青 → 登峰造极（等级 L 需累计 60·L·(L+1)/2 道韵，每有效活动秒 +0.1）。
- 同一时间窗口只结算一种活动（前台采样天然单份，多进程并存不重复结算）。
- 程序后台运行、电脑锁屏或约 90 秒无人操作时停止主动道韵结算（`GetLastInputInfo` 空闲判定，获取失败按空闲处理）。
- 基础挂机修炼完全独立：暂停修炼不影响百业，关闭百业不影响修炼；隐藏桌宠期间照常识别前台工作。
- 单次节拍最多结算 3 秒，界面卡死不会伪造活动时长。

### 3. 百业道碑界面

修行面板新增「百业道碑」入口。道碑展示：

- 已发现的修行道途（名称、等级称谓、道韵进度条、当前活动高亮）与未发现的「？？？」空碑；
- 当前识别或手动选择的活动与来源；
- 道韵获取记录（最近 40 条，只含道途/数量/来源类别）；
- 机缘与传承：已解锁机缘、已获传承、未解锁机缘的模糊提示。

视觉上沿用修行面板的国风淡紫底与卡片语言，结构优先，预留后续完整美术升级。

### 4. 隐私与控制

- 首次开启任一识别模式前，弹出完整功能说明（识别什么、永不读取什么、数据只存本机、如何关闭），确认后才生效；道碑内可随时重读说明。
- 三种方式随时切换：关闭活动识别 / 仅识别应用类别 / 应用类别 + 手动活动标记。
- 所有分类与结算数据保存在本机 `baiye-v1.txt`；关闭识别立即停止新的活动采样（内存模式即时生效并结算当前片段），已有道韵与记录保留，不影响普通挂机修炼。

### 5. 第一条多道共鸣：阵道 + 天机道 → 天机演算

- 条件：阵道与天机道各累计 120 道韵。由于道韵只在前台对应活动时结算、且同一窗口只结算一种活动，双达标必然意味着玩家在不同时间分别编程与使用 AI。
- 触发后：解锁机缘「天机演算」，获得传承「天机阵图」与 120 修为奖励（经修仙主进度的公开入口发放，百业模块不反向依赖）；道碑、获取提示与战斗通报同步呈现。
- 机缘只触发一次；事件结构（`BaiyeEncounterDef.Kind/Payload`、条件数组、奖励负载）已为连续机缘、特殊 NPC 与软件秘境预留。

## 二·五、收尾整改记录（PR #2 审查意见）

**A1 机缘奖励一致性（幂等结算）**。奖励发放改为三段协议：机缘解锁先落百业存档（`enc.<id>`）→ 修为入账并把 `grant.<id>` 标记写进修仙存档 → 百业存档补 `grant.<id>` 完成标记。修仙存档新增可选的外部奖励台账键（旧版本读取时忽略未知键）。任一窗口异常退出/断电后重启对账：修仙侧已有标记则只补百业侧标记（不重复发放）；两侧都无标记则重新发放（不永久丢失）；进程内另有入账集合防止同会话重复。写盘失败不标完成，后续节拍持续补试。

**A2 隐私说明的底层约束**。追踪器在每次节拍的入口处检查首次说明确认：未确认时无论存档中保存什么识别模式，都不调用前台/空闲探针、不结算道韵（测试用「一探即失败」的合成探针验证零调用）。损坏存档、缺失确认字段、越界模式（如 mode=7）均有测试覆盖。

**A3 获取记录完整性**。退出前 `Seal()` 把未结束的活动片段落进获取记录；启动时 `ReconcileLog` 对账：道韵总量超过记录合计的部分补一条「历史结算补记」，保证每份道韵重启后都有合理记录。模式切换与手动标记变更本身就会结算当前片段。

**A4 性能与手动标记**。前台探测从「每绘制节拍一次」降为固定节奏采样（默认 2 秒），间隔期沿用缓存状态结算，活动时长分毫不差（测试验证 660 拍只探测约 330 次且总量不变）。道碑显示「手动标记生效中」状态、新增「取消标记」快捷按钮；手动标记持续超过 30 分钟会在当前活动行提示已生效时长与取消方式，避免长期误分类。

## 四、已知问题与后续建议

1. 自动识别表为静态进程名清单，覆盖主流应用；冷门软件由手动标记兜底。后续可引入用户自定义「进程名 → 道途」映射（仍不读内容）。
2. 浏览器活动统一归游历道，具体细分依赖玩家手动标记；不计划读取浏览历史或标签页标题。
3. 机缘目前只有「天机演算」一条；事件结构已预留连续机缘、特殊 NPC 与软件秘境，待第三纵切充实。
4. 道碑为结构清晰的功能美术，等待整体美术升级统一翻新。
5. 建议后续版本把道韵等级与功法/装备产生轻度联动（如阵道等级解锁阵图外观），需单独评审数值。
