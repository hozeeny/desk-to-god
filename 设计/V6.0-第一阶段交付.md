# 《桌面修仙传》V6.0｜第一阶段交付说明

> 分支：`feature/v6-persistent-cultivation` · 基线：骑士助手 v5.4（main）+ V6 实验代码（设计基线文档与 CultivationCore.cs）

## 一、本阶段实际完成的功能

### P0 · 基础架构与安全整改

1. **纯修仙模式（默认）**：游戏事件、虚拟奖励结算与真实系统维护彻底解耦。未授权时，击败任何妖物（文件怪、内存 Boss、磁盘 Boss）只结算修为/经验等虚拟奖励——不删除真实文件、不回收其他进程工作集、不触碰网络规则。磁盘 Boss 在未授权时保持纯警示形态，不再绑定真实清理候选。
2. **双范围独立维护授权**：修行面板提供「授权文件清理」「授权内存维护」两个独立开关（默认均关，各自确认弹窗写明范围），授权状态分别持久化到 `maintenance-consent.txt`；开启 fail-closed（写盘失败保持关闭），关闭立即生效并尽快取消未开始与进行中的对应任务。v5.4 的真实清理管线原样保留，授权开启后完整可用。
3. **权限边界**：`app.manifest` 从 `requireAdministrator` 改为 `asInvoker`，移除启动时强制 runas 提权。纯修仙、桌面冒险、临时文件战斗均不需要管理员；仅网络监控/限速/断网需要管理员，主界面底部新增「以管理员身份重启 · 启用网络管理」入口（`--elevated-restart` 握手避免双开冲突），非管理员时相关按钮自动禁用。
4. **存档兼容**：旧版 `adventure-v1.txt` 作为运行时战斗档继续以不变 v1 格式读写（v5.4 可直接读取），首次启动时一次性冻结备份为 `.v54-backup` 供回退；新修仙档 `cultivation-v2.txt` 独立建档，版本化（v2），原子写入 + `.bak` 备份恢复，可读取并迁移 V6 实验分支的 v1 档案（补齐道号/功法，进度无损）。
5. **主循环解耦**：修炼进度使用独立的 Stopwatch 真实时间差值累计，不经过渲染帧的 0.1 秒 dt 封顶；单次 tick 最多补记 3 秒，UI 卡死/睡眠恢复不会虚报修为。

### P1 · 持续修仙桌宠

1. **角色与灵根**：道号（首启动随机生成，持久化）、灵根（金/木/水/火/土/杂，首启动随机觉醒，**不由电脑配置决定**，已有合法灵根绝不重抽）、当前境界、修为、功法、修行路线。灵根与路线都不锁死，功法随时改修。
2. **境界与修炼**：炼气至筑基起共 8 境界数据结构；每境 20 层，1—9 层正常积累、第 10 层起可主动破境（成功率 10% 起逐层递增）、第 20 层保底 100%；破境失败只消耗本次灵气，根基无损。全部数值集中在 `CultivationBalance`（基础速率、层成本、破境成本/概率、设备分档系数、妖物调度与击杀奖励），便于后续平衡调整。
3. **挂机成长**：运行时持续积累基础修为（0.6 修为/秒起），不依赖临时文件、CPU/内存状态或网络；设备只按固定能力分档（清灵/凡灵/浊灵洞天，逆境加成 1.0/1.08/1.18），不读取实时负载，不鼓励制造卡顿。
4. **战斗系统**：复用现有自动索敌/战斗/装备机制；新增虚拟妖物事件调度器（修炼活跃时间每 45～95 秒一只），即使电脑完全干净也有普通妖物来访；击杀获得修为（普通 6—10、Boss 30—50）与经验。怪物种类名称修仙化（白骨妖兵/碧渊水灵/独眼山魈/夜行蝠妖/幻菌菇妖），素材本阶段复用 v5 渲染资产。敌人总数仍受 11 个（9 普通 + 2 Boss）硬上限约束，渲染压力与历练机会解耦。
5. **存档系统**：修仙档随主存档节奏持续保存（每 20 秒及晋级/破境/切换功法等关键事件即时保存），退出时收尾保存；异常退出后自动从 `.bak` 恢复；断网、隐藏、收托盘均不影响修炼与存档。自动作战偏好随修仙档持久化，默认开启。
6. **无人值守挂机**：修士默认自主作战（可在修行面板改手动，选择持久保存）；力竭后入定调息约一分钟自行恢复并按偏好恢复作战，永不永久停死；断网时入定吐纳，本地修炼与战斗继续；无固定通关时间，不要求定时上线。
7. **基础交互**：主界面标题区与桌面角色标签显示境界（如「炼气 · 第3层」）；修行面板（原装备栏）展示道号、灵根、洞天档位、境界层数、修为进度条、功法下拉、破境按钮（含成功率与确认）、暂停/恢复修炼、两项真实维护授权开关与纯修仙模式说明；战斗数值标注为「战斗Lv.（与修仙境界相互独立）」。桌面角色隐藏/暂停/低干扰常驻保留。

### 暂不开发（仅预留接口）

百业证道与多道共鸣、软件灵域与千面蜃楼、完整炼丹炼器与洞府经营、桌面破境大型演出、宗门/道侣/交易/多人联机。`CultivationProgress.DaoPath`、`CultivationIdentity`、`CultivationTechnique.School` 与调度器均为后续扩展预留了数据结构。

## 四、验收整改记录（第二轮）

对应产品负责人验收意见的六项整改：

1. **旧存档兼容**：`adventure-v1.txt` 明确定位为「运行时战斗档」（v1 格式继续写入，v5.4 可直接读取）；首次启动一次性冻结备份 `adventure-v1.txt.v54-backup`，此后永不再写，回退 v5.4 时用备份覆盖运行时档即可。新增模型自测覆盖：无旧档不伪造备份、首次冻结、重复启动不覆盖、v6 写入后 v5.4 格式可读、备份回退恢复原值。
2. **灵根分配**：`SpiritRoot` 默认改为空（待觉醒），`EnsureIdentity` 区分首次创建（六项灵根随机分配）与正常读取/迁移（已有合法灵根绝不重抽，非法值修复一次）。自测覆盖：新档必得合法灵根、100 个种子六种灵根全覆盖、`mixed`/`fire` 等已有灵根保留、存档往返持久化。
3. **无人值守挂机**：自动作战默认开启并随修仙档持久化（`autobattle=`，与真实维护授权完全独立）；力竭后入定调息约 60 秒自行恢复并按偏好恢复自动作战，永不永久停死；断网映射为入定吐纳，本地修炼与战斗继续；无固定通关时间、无定时上线要求。冒烟新增调息复活、手动偏好保留、断网不误判三项断言，并经实机验证（见上表）。
4. **维护授权完善**：拆分为「文件清理」「内存维护」两项独立授权（新 `MaintenanceConsentStore`）。开启 fail-closed：先原子写盘成功才生效，写盘失败保持关闭并回滚内存态；关闭立即生效，进行中的对应任务收到取消并反馈实际结果，文件更新失败时删除旧授权文件防止死灰复燃，仍失败则明确告知手动处理路径。旧版单一 `consent=1` 档案读取时升级为双授权。授权文件被其他进程独占等异常有专项自测（19 项）。
5. **成长数据统一**：界面明确区分两套数值——修仙侧显示「境界 · 第N层」，战斗侧标注「战斗Lv.N（战斗熟练等级，与修仙境界相互独立）」，不再混用「Lv.」。旧战斗系统本阶段保留。**后续迁移建议**：下一阶段把战斗经验按固定比率折算为修为注入修仙档（例如 1 经验 = 20 修为，一次性补发并写入迁移标记），武器保留为「法宝」外观映射，战斗等级随后退役为纯展示字段，最终由境界完全取代；迁移需保持 `adventure-v1.txt` 可读以支持回退。
6. **实机验证**：见第三节实机验证记录表；未执行项已明确标注。

## 五、未完成项目与已知风险（第二轮更新）

1. **数小时级 soak 未执行**：180 秒实机挂机内存/线程/句柄稳定，更长时段建议合并前挂机一晚观察修为曲线与内存占用。
2. 未授权模式下击杀文件怪后，其临时文件保留且本次会话不会复活为怪物（`represented` 机制）；手动「重新扫描」会重新生成——击杀奖励较小，暂不构成刷分风险，后续可加击杀衰减。
3. 标准用户账户已通过 `--selftest` 全量自测（含清理与授权套件）；**标准用户完整 GUI 会话未实测**（需交互桌面），普通权限功能降级路径仅有代码级与冒烟保障。
4. **断网挂机未实机验证**（服务器不宜断网）；代码级保障为 Offline→入定映射与状态机自测。
5. 内存 Boss 仍由真实内存压力（>70%）触发出现；未授权时它只是普通战斗目标。后续可考虑为纯修仙模式增加虚拟心魔 Boss，完全脱离系统指标。
6. 美术仍为 v5 骑士/怪物素材（指令允许本阶段复用）；地区皮肤、装备体系沿用旧体系，修仙化重绘属后续阶段。
7. 破境目前是确认弹窗 + 文案反馈，桌面破境演出属第二纵切。
8. EXE 文件名仍为「骑士助手.exe」以兼容打包脚本与 Assets 引用；对外品牌文案已切换为「桌面修仙传」。

## 六、如何运行和验证当前版本

```powershell
git clone https://github.com/hozeeny/desk-to-god.git
cd desk-to-god
git switch feature/v6-persistent-cultivation
powershell -NoProfile -ExecutionPolicy Bypass -File ".\源代码\build.ps1"
.\源代码\bin\骑士助手.exe --selftest          # 退出码 0
.\源代码\bin\骑士助手.exe --adventure-smoke   # 退出码 0
.\源代码\bin\骑士助手.exe                     # 正常启动（普通权限即可）
```

验证要点：

1. 启动后桌面出现修士，标签显示「炼气 · 第N层」，层数随时间自然推进；修士默认自主作战，无需点击。
2. 右键修士 → 修行面板：道号、灵根（六种随机之一）、功法、修为进度条可见；功法可切换；暂停/恢复生效。
3. 不制造任何临时文件，等待约 1 分钟：虚拟妖物出现并被自动击败，修为增加，且 `%LOCALAPPDATA%` 的 Temp 无任何文件被删除。
4. 修行面板分别勾选「授权文件清理」「授权内存维护」并确认后，对应真实维护才生效；取消任一授权不影响另一项。
5. 关闭重开：境界、修为、道号、灵根、功法、自动作战偏好与两项授权状态均恢复；删除 `cultivation-v2.txt` 后会从 `.bak` 恢复；`adventure-v1.txt.v54-backup` 保持冻结。
6. 力竭验证：修士被打倒后无需操作，约一分钟入定调息自行恢复并继续修行。
7. 网络管理：普通权限下主界面提示并显示「以管理员身份重启」；重启后网络监控恢复（需 WinDivert 文件在 EXE 旁）。
