# 《桌面修仙传》V6.0｜第一阶段交付说明

> 分支：`feature/v6-persistent-cultivation` · 基线：骑士助手 v5.4（main）+ V6 实验代码（设计基线文档与 CultivationCore.cs）

## 一、本阶段实际完成的功能

### P0 · 基础架构与安全整改

1. **纯修仙模式（默认）**：游戏事件、虚拟奖励结算与真实系统维护彻底解耦。未授权时，击败任何妖物（文件怪、内存 Boss、磁盘 Boss）只结算修为/经验等虚拟奖励——不删除真实文件、不回收其他进程工作集、不触碰网络规则。磁盘 Boss 在未授权时保持纯警示形态，不再绑定真实清理候选。
2. **独立维护授权**：修行面板提供「授权真实系统维护」开关（默认关闭，开启需确认弹窗），授权状态单独持久化到 `maintenance-consent.txt`；关闭时未开始的清理任务安全转为虚拟结算，已开始的任务保留核算权直到收尾。v5.4 的真实清理管线原样保留，授权开启后完整可用。
3. **权限边界**：`app.manifest` 从 `requireAdministrator` 改为 `asInvoker`，移除启动时强制 runas 提权。纯修仙、桌面冒险、临时文件战斗均不需要管理员；仅网络监控/限速/断网需要管理员，主界面底部新增「以管理员身份重启 · 启用网络管理」入口（`--elevated-restart` 握手避免双开冲突），非管理员时相关按钮自动禁用。
4. **存档兼容**：旧版 `adventure-v1.txt` 原样保留、绝不覆盖；新修仙档 `cultivation-v2.txt` 独立建档，版本化（v2），原子写入 + `.bak` 备份恢复，可读取并迁移 V6 实验分支的 v1 档案（补齐道号/功法，进度无损）。
5. **主循环解耦**：修炼进度使用独立的 Stopwatch 真实时间差值累计，不经过渲染帧的 0.1 秒 dt 封顶；单次 tick 最多补记 3 秒，UI 卡死/睡眠恢复不会虚报修为。

### P1 · 持续修仙桌宠

1. **角色与灵根**：道号（首启动随机生成，持久化）、灵根（金/木/水/火/土/杂，随机分配，**不由电脑配置决定**）、当前境界、修为、功法、修行路线。灵根与路线都不锁死，功法随时改修。
2. **境界与修炼**：炼气至筑基起共 8 境界数据结构；每境 20 层，1—9 层正常积累、第 10 层起可主动破境（成功率 10% 起逐层递增）、第 20 层保底 100%；破境失败只消耗本次灵气，根基无损。全部数值集中在 `CultivationBalance`（基础速率、层成本、破境成本/概率、设备分档系数、妖物调度与击杀奖励），便于后续平衡调整。
3. **挂机成长**：运行时持续积累基础修为（0.6 修为/秒起），不依赖临时文件、CPU/内存状态或网络；设备只按固定能力分档（清灵/凡灵/浊灵洞天，逆境加成 1.0/1.08/1.18），不读取实时负载，不鼓励制造卡顿。
4. **战斗系统**：复用现有自动索敌/战斗/装备机制；新增虚拟妖物事件调度器（修炼活跃时间每 45～95 秒一只），即使电脑完全干净也有普通妖物来访；击杀获得修为（普通 6—10、Boss 30—50）与经验。怪物种类名称修仙化（白骨妖兵/碧渊水灵/独眼山魈/夜行蝠妖/幻菌菇妖），素材本阶段复用 v5 渲染资产。敌人总数仍受 11 个（9 普通 + 2 Boss）硬上限约束，渲染压力与历练机会解耦。
5. **存档系统**：修仙档随主存档节奏持续保存（每 20 秒及晋级/破境/切换功法等关键事件即时保存），退出时收尾保存；异常退出后自动从 `.bak` 恢复；断网、隐藏、收托盘均不影响修炼与存档。
6. **基础交互**：主界面标题区与桌面角色标签显示境界（如「炼气 · 第3层」）；修行面板（原装备栏）展示道号、灵根、洞天档位、境界层数、修为进度条、功法下拉、破境按钮（含成功率与确认）、暂停/恢复修炼、真实维护授权开关与纯修仙模式说明。桌面角色隐藏/暂停/低干扰常驻保留。

### 暂不开发（仅预留接口）

百业证道与多道共鸣、软件灵域与千面蜃楼、完整炼丹炼器与洞府经营、桌面破境大型演出、宗门/道侣/交易/多人联机。`CultivationProgress.DaoPath`、`CultivationIdentity`、`CultivationTechnique.School` 与调度器均为后续扩展预留了数据结构。

## 三、构建和测试结果

环境：Windows x64，.NET Framework 4.8 自带 `csc.exe`，管理员 PowerShell。

- `源代码/build.ps1`：编译通过，输出 `源代码/bin/骑士助手.exe`。
- `--selftest`：全部通过，含新增 `Cultivation: 21 checks`、`Cultivation encounter: 6 checks`；既有清理安全（57 项）、战斗模型（92 项）、渲染（73 + 840 项）等全部保持绿色。
- `--adventure-smoke`：48 项通过（合成文件与内存回收模拟），新增授权门控断言：未授权时文件怪/Boss 击杀不启动清理工作器、不触发内存回收；虚拟妖物只给修为且不留文件副作用。
- `--preview` / `--equipment-preview`：主界面与修行面板渲染正常（预览图见 PR 描述）。
- 退出码均为 0。

## 四、未完成项目与已知风险

1. 长时间连续运行、多次启停、断网续修、异常断电恢复只通过单元/集成级验证（原子保存 + 备份回退 + 存档迁移用例）；**未做真机数小时挂机 soak 测试**，建议合并前实机挂机一晚观察修为曲线与内存占用。
2. 未授权模式下击杀文件怪后，其临时文件保留且本次会话不会复活为怪物（`represented` 机制）；手动「重新扫描」会重新生成——击杀奖励较小，暂不构成刷分风险，后续可加击杀衰减。
3. 普通权限运行未经真实标准用户账户验证（本机为管理员账户）；理论上 Temp 清理与同会话工作集回收在标准权限可用，建议用标准账户实测一遍。
4. 内存 Boss 仍由真实内存压力（>70%）触发出现；未授权时它只是普通战斗目标。后续可考虑为纯修仙模式增加虚拟心魔 Boss，完全脱离系统指标。
5. 美术仍为 v5 骑士/怪物素材（指令允许本阶段复用）；地区皮肤、装备体系沿用旧体系，修仙化重绘属后续阶段。
6. 破境目前是确认弹窗 + 文案反馈，桌面破境演出属第二纵切。
7. EXE 文件名仍为「骑士助手.exe」以兼容打包脚本与 Assets 引用；对外品牌文案已切换为「桌面修仙传」。

## 五、如何运行和验证当前版本

```powershell
git clone https://github.com/hozeeny/desk-to-god.git
cd desk-to-god
git switch feature/v6-persistent-cultivation
powershell -NoProfile -ExecutionPolicy Bypass -File ".\源代码\build.ps1"
.\源代码\bin\骑士助手.exe --selftest          # 退出码 0
.\源代码\bin\骑士助手.exe --adventure-smoke   # 退出码 0
.\源代码\bin\骑士助手.exe                     # 正常启动（普通权限即可）
```

验证要点：

1. 启动后桌面出现修士，标签显示「炼气 · 第N层」，层数随时间自然推进。
2. 右键修士 → 修行面板：道号、灵根、功法、修为进度条可见；功法可切换；暂停/恢复生效。
3. 不制造任何临时文件，等待约 1 分钟：虚拟妖物出现，点击或自动规划击败后修为增加，且 `%LOCALAPPDATA%` 的 Temp 无任何文件被删除。
4. 修行面板勾选「授权真实系统维护」并确认后，击败文件怪才会真实清理旧临时文件。
5. 关闭重开：境界、修为、道号、灵根、功法与授权状态均恢复；删除 `cultivation-v2.txt` 后会从 `.bak` 恢复。
6. 网络管理：普通权限下主界面提示并显示「以管理员身份重启」；重启后网络监控恢复（需 WinDivert 文件在 EXE 旁）。
