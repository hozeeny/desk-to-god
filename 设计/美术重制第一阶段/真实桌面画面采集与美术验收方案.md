# 真实桌面画面采集与美术验收方案

日期：2026-10-18。源码基线：`main / 5f8151a`。工作分支：`feature/v6-art-foundation`。

整体方向已确认为 **A｜国漫仙侠·精致微缩风**。具体人物造型仍在设计阶段，后续由产品方提供确认稿与素材。本方案和本轮旧素材画面用于验证采集与隔离能力，不代表已制作新角色，也不批准新的动画或渲染改造。

## 一、验收必须回答的问题

1. 资产经实际生产渲染器缩小后，人物、妖物、法器和文字能否看清？
2. 相同帧经 Windows 透明桌面窗口显示后，是否仍完整、无黑底白边、没有位置偏移？
3. 界面是否真的显示，而非仅收到脚本退出码或生成一张有效但空白的 PNG？
4. 验收是否始终使用演示内存状态或独立测试档，不依赖、删除、覆盖长测中的任何真实存档？

四项均需有证据。图像自动检查通过后仍须逐张目视检查；脚本返回零不单独构成美术验收。

## 二、两条画面采集链

| 方式 | 实际链路 | 能证明的范围 |
| --- | --- | --- |
| 静态渲染导出 | 当前 `AdventureRenderer.Render` → 原始透明帧 → 浅色、深色合成预览；真实 `AdventureEquipmentForm` 单独导出 | 分件合成、裁切、尺寸、透明边及普通 WinForms 控件绘制 |
| 实际桌面截图 | 同一透明帧 → 生产 `KnightLayeredWindow.Present` → `UpdateLayeredWindow` → Windows 桌面合成 → 原生 `BitBlt` 抓取 | Windows 透明窗口确实显示了人物、妖物、地标，并与真实修行表单共同出现 |

`DrawToBitmap` 仅用于普通 WinForms 修行表单，不再用于透明分层窗口。后者原有截图为空白，即使退出码为零也不合格。新 `DesktopFrameCapture` 使用 `SRCCOPY | CAPTUREBLT` 读取桌面合成像素，截图保存为 RGB；桌面图没有可用的透明通道，不能把屏幕缓冲误存为全透明 PNG。

历史 `MortalGuiAccept` 的截图委托已接到同一桌面捕获函数；截图出错会记入 FAIL，不再吞掉异常。长达约十三分钟的完整凡人成长验收与美术采集是两种验收，本轮不把短画面探针当作长流程重跑。

## 三、独立采集场景

采集工具位于 `源代码/验证工具/ArtCaptureProbe.cs`，以独立入口编译，调用当前生产渲染器、透明窗口类和真实修行表单；不运行正式程序入口，不争用正式游戏单实例互斥锁。

- 主角帧为 220×240，普通妖物为 130×170，地标为 200×280；均使用现有旧素材。
- 控制器使用 `demonstrationOnly=true`，暂停演示节拍，修行数据只在内存中设置，三项真实维护授权均关闭。
- 角色、妖物和地标是真实独立透明顶层窗口；右侧为真实修行与装备表单。浅色和深色底板仅用于检查透明合成，不是游戏新场景。
- 截取范围限于工具自己的 1280×830 采集区域。工具应在可用桌面至少 1320×900、已解锁且窗口未被遮挡的环境运行。
- 若进程隐藏启动抑制首次窗口显示，工具重新显示自己的底板；不能接受其他应用内容充当验收背景。
- 关闭时只释放本探针创建的对象和窗口，不按游戏进程名清理，也不调用旧 GUI 启动器的全进程 cleanup。

这验证的是静态生产渲染与 Windows 合成链，不验证新风格、新境界外观、动画流畅度、完整战斗或长测性能。

## 四、运行与产物

在独立美术 worktree 根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\源代码\验证工具\Run-ArtCapture.ps1"
```

仅执行非桌面图像校验：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\源代码\验证工具\Run-ArtCapture.ps1" -SelfTestOnly
```

脚本以 .NET Framework x64 编译器构建，产物放入当前 worktree 下全新的 `artifacts/art-capture/<时间与随机编号>/bin`。不覆盖 `源代码/bin`、`正式版` 或 main 中的 EXE。脚本使用 UTF-8 BOM，适配 Windows PowerShell 5.1。

| 产物 | 用途 |
| --- | --- |
| `hero-alpha.png`、`monster-alpha.png`、`landmark-alpha.png` | 原始渲染透明帧，检查真实轮廓和裁切 |
| `ui-static.png` | 真实修行表单静态导出 |
| `static-light.png`、`static-dark.png` | 静态渲染合成预览 |
| `desktop-light.png`、`desktop-dark.png` | 实际 Windows 桌面合成截图 |
| `build-identity.json` | 基线提交、工作分支、实际编译源码与 EXE 哈希；工作树未提交时明确标记为 working-tree |
| `capture-report.json` | 资产哈希、窗口句柄、进程号、屏幕区域、像素匹配结果、截图哈希 |
| `*.stdout.log`、`*.stderr.log` | 运行记录及失败原因 |

失败候选图片可能保留在本地 artifacts 便于诊断；只有全部像素检查结束才写成功报告。成功报告仍带 `humanReviewRequired=true`。交付图片必须经人工看图确认，并另附验收记录。

## 五、自动拒收与人工验收

自动检查包括十项：拒绝全透明与纯灰空白；接受真实主角、妖物、地标渲染帧；拒绝桌面缺失角色或坐标错位；接受正确前景；验证透明边显示预期底色；拒绝错误底色。

桌面帧逐像素抽样对照相同生产渲染帧：不透明主体至少有 100 个采样点，允许小幅显示误差后匹配率须达 93%；充分透明区域至少 100 点时，底色匹配率须达 95%。此门槛用于捕获层缺失、遮挡和位置错误，不评价画风是否正确。

人工必须打开原文件检查：人物与妖物轮廓完整、五官可辨；武器未断裂、手未脱离握柄；脚与地面关系清楚；建筑未被裁断；真实修行面板标题、内容与控件可见；浅深两种底色下没有矩形底、明显黑边或白边；没有误拍其他应用。需要时放大查看，再回到 100% 的实际尺寸判断。

后续产品确认稿进入接入阶段后，补验待机、左右跑步、左右攻击、调息与恢复，以及 176×192、220×240、264×288 三档主角尺寸。现有眼睛取色等旧素材特征测试需要按新资产重新评审，不能用旧颜色强制约束新设计。

## 六、冒烟测试存档隔离

原失败点是 Growth 烟测清空临时路径覆盖后，检查当前用户的 `lingyu-v1.txt` 必须不存在。长期游戏或长测已创建此文件时，测试会错误失败。

本轮最小修复保留演示模式不落真实档的语义：Native 烟测明确检查自己的临时百业、灵域 fixture；模拟重启后恢复同一临时路径。Growth 最后检查实际写入过的故障注入目录已清理，同时保留无网络连接、无真实清理收益的断言。测试不删除当前用户档，不将默认路径文件不存在作为成功条件。

回归入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\源代码\验证工具\Run-SmokeIsolationRegression.ps1"
```

回归宿主仅在编译副本中，把六个默认存档路径初始化注入到隔离目录；每处要求恰好匹配一次，不更改被测断言、分支或算法。分别预置“已有灵域档”和“没有灵域档”，校验整个默认档目录的文件名、字节、时间、子目录和文件写事件不变。日志和源码、编译副本哈希均落到当前 worktree 的 artifacts。该宿主不能单独证明未改路径的正式二进制通过，需另运行当前原始构建的 `--selftest` 与 `--adventure-smoke`。

## 七、当前交付与后续边界

整体风格已确认，人物造型尚未定稿。本轮图片均为旧素材的技术取证；没有新角色图、正式素材替换或核心渲染算法修改。新的 PNG、rects 与锚点接入，等待产品方提供确认稿和素材后再开展。

实际验证状态与人工看图结果保存在同目录的 `验收基线/验收记录.md`；未经该记录确认的候选图不作为美术验收基线。
