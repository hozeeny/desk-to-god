## 一、目标与边界

把现有骑士桌宠资产，逐步重制为具有统一识别、可信材质与成长表现的修仙桌宠。玩家应在桌面实际显示尺寸下看清“这是自己的同一位修士”，并从衣着、轮廓、姿态与材质读出凡人、炼气、筑基的变化。

整体方向现已确定为高质量 2.5D 国漫仙侠，约 2.8—3 头身，强调布料、玉石、金属的材质层次，避免廉价玩具感。本轮整理已确认方向与技术交付要求，接下来等待产品方提供人物确认稿和素材，由 Codex 负责后续技术工作；暂不生成图片、替换素材或修改渲染代码。原画质量不能由大图细节数量代替；220×240 像素中的脸、衣领、袖形与脚底关系，才是桌面角色的主要质量依据。

| 本轮形成的成果 | 本轮不推进的事项 |
| --- | --- |
| 可追溯的美术问题、已确认的全局方向、全局资产矩阵、三阶段角色方案、拆件与验收要求；存档隔离与真实画面采集基础设施修复 | 生成新图片、替换素材、修改渲染代码、大规模动画系统重写、核心玩法改动、更新正式版、发布或合并分支 |
| 区分已确认风格与仍待核准的人物细节，整理产品供稿及技术接收清单 | 把人物性别、年龄、脸型、发型、配色或配件建议写成已核准造型 |

存档隔离与真实画面采集基础设施修复仍属于此前已授权范围；本次风格确认不扩大新美术制作或渲染接入范围。

## 三、当前 V5 美术与 V6 内容之间的问题

| 问题 | 已有表现或依据 | 对重制的影响 |
| --- | --- | --- |
| 主体世界观混杂 | 骑士、剑修、武士、牛仔、青蛙和街头人物共用一套桌宠结构；建筑与武器也跨题材 | 产品缺少一眼可识别的修仙主形象；先建立标准修士，再决定旧主题如何保留 |
| 成长缺乏形体差异 | 当前主角渲染状态有主题、武器、战斗等级和文字，未携带境界、灵根、功法对应的外观方案；境界主要体现为标签 | 凡人到筑基不能只换颜色、加光环；需先设计衣着和姿态分级，再另行接入 |
| 材质趋同、细节分布拥挤 | 现有角色与器物普遍使用较强外轮廓、亮边和高光；小尺寸中衣领、金边、肩部饰件容易挤在一起 | 新方案要用布、皮、玉、金属各自的反光和结构建立层次，减少无功能装饰 |
| 妖物语义不足 | 普通、精英、蜃楼镜妖与主镜的玩法身份尚无完整独立视觉体系 | 需要物种轮廓、精英结构和灵域特征三级区别，避免只提高亮度 |
| 力竭语义与画面冲突 | 现有逻辑为调息后恢复，画面仍复用墓碑、幽灵、破土等旧表现 | 候选改为虚弱、收势、入定和复起；恢复时间与结算规则不变 |
| 功能界面尚未统一 | 修行、破境、百业、灵域、洞天已有功能窗体，仍以文字和标准控件为主 | UI 先整理信息层级、状态和图标，再统一皮肤，不能用插画遮盖重要操作 |
| 品牌仍偏向旧骑士 | `KnightBrand` 共用 `OTHER` 皮肤的头部，现有升级光效还出现 `LEVEL UP!` | 图标与升级提示要跟随产品身份统一；资产中不烘焙多余英文和装饰字 |

现有角色已具备连续骨骼和手绘分件基础，不应把重制等同于换成另一张大立绘。头颈连接、持握、脚底接地、前后遮挡与双向移动的既有要求，都必须继续验收。

## 四、已确认方向：A｜国漫仙侠·精致微缩风

**产品方于 2026-10-18 确认整体方向。** 此前的候选风格比较已被本次决策取代，不再保留为待选项。

| 已确认事项 | 设计含义与质量要求 |
| --- | --- |
| 高质量 2.5D 国漫仙侠 | 有明确体积、层次与光照，保留国漫仙侠的人物气质和精致原画表现；不以堆金边、泛光或密纹代替质量 |
| 约 2.8—3 头身的微缩角色 | 在桌面小尺寸中保留面容与动作可读性，比例紧凑但身体舒展；具体落点随产品确认稿核对，不改变已确认范围 |
| 布料、玉石、金属材质 | 布料褶皱与柔暗面、玉石温润透感、金属集中高光分别成立；避免全身同一种塑料反光和廉价玩具感 |
| 同一修士的三阶段成长 | 凡人朴素、炼气清逸、筑基沉稳，面容核心特征一致；依靠服装、姿态与灵气结构变化，不只换色或增加光效 |
| 全局资产统一 | 主角、妖物、武器、洞天、秘境和 UI 使用同一套形体、材质、光照与细节密度规则，品牌入口同步统一 |
| 后续分工与当前限制 | 产品方提供具体人物确认稿与素材，Codex 负责技术；当前等待供稿，暂不生成图片、替换素材或修改渲染代码 |

透明分件与无多余装饰文字继续作为交付约束。为适配现有右向骨架，Codex建议采用右向四分之三视角与画面左上主光；这两项属于技术建议，具体视角和光向以产品确认稿为准。具体人物造型尚未定稿，不采用现成艺术家的专属风格作为模仿目标。

| --- | --- | --- |
| 人物年龄感与性别表达 | 年轻、偏中性的修士作为讨论起点；具体年龄感、性别和面相见角色方案 | 待产品确认 |

## 五、全局视觉规则

1. **人物先于特效。** 关掉灵气、去掉阶段标签后，仍能辨认角色和成长阶段。脸、发型主轮廓、领口结构是第一层识别；配色是辅助。
2. **变化来自生活与修行。** 凡人朴素、炼气清逸、筑基沉稳；通过衣着结构、姿态和灵气秩序成长，不把凡人画得滑稽，也不把筑基直接做成帝王或重甲神将。
3. **材质各有依据。** 粗布用大褶与柔暗面，细织物用较连续的明暗，皮革用窄而钝的反光，玉用局部透润，金属用少而明确的亮暗反差。任何方向都要在缩小后保留区别。
4. **主次控制在小尺寸完成。** 最亮、最清晰的区域优先给脸和手部动作；衣纹与背景不抢主体。保留透明空间，不烘焙地面、展示卡、标题或边框。
5. **身份与玩法状态分开。** 境界、灵根、功法、武器、精英状态分别设计，不由一层全身滤色承担所有含义；后续需要哪些状态字段，交由技术接入方案另行明确。
6. **文字为操作服务。** 名称、数值、必要单位由界面绘制；资源图不带英文口号、伪文字、编号或水印。真实功能名称和必要技术单位不因美术重制被擅自更名。

## 六、全局资产矩阵与建议制作顺序

下表规划完整资产系统，**不表示本轮已授权全部制作**。当前先等待产品确认稿与素材，表中的顺序是后续接收与技术核验依赖，不是生成指令。数量是可辨识的类型与状态范围。

| 类别 | 现有资产或内容基线 | 重制资产与最小状态 | 一致性要求 | 建议顺序 |
| --- | --- | --- | --- | --- |
| 角色 | 六类旧主题分件；共用骨骼与武器 | 标准修士凡人/炼气/筑基三阶段；站立、行走、攻击、格挡、受击、调息、恢复的表现要求 | 同一人、同一视角和光向；服装轮廓分级；以产品提供的确认稿为准 | 1：接收人物确认稿与标准素材；2：三阶段与动作验证 |
| 妖物 | 骷髅、软泥、小恶魔、蝙蝠、蘑菇、首领以及邪恶分身路径 | 普通妖物家族、精英结构特征、镜妖与主镜灵域特征；受击/败退可复用的效果语言 | 普通与精英不只染色；首领需有身份轮廓，镜面材质不覆盖战斗读数 | 3：先一个普通妖物与其精英，再镜妖/主镜，最后扩家族 |
| 武器与法器 | 七类武器轮廓与装备图标 | 保留现有战斗类别的外观重制；持握点、攻击端、近远程结构、背包图标 | 体量和手掌匹配；图标与手持同物；射程、冷却、伤害、解锁规则不变 | 2：一个持握验证件；4：按类别扩展 |
| 洞天与灵域 | 旧主题地标；灵田、丹炉、器位；千面蜃楼及其他灵域入口 | 灵田未种/生长/成熟，丹炉空闲/炼制/可收，器位空置/铸灵/已成；洞天入口与蜃楼关键场景 | 建筑材质、比例和角色同一世界；状态通过结构与局部变化识别；未开放灵域不做伪可玩入口 | 5：先洞天一组功能状态，再蜃楼一组，最后其余已确认内容 |
| UI | 修行、装备、破境、百业、灵域与洞天窗体 | 字体/间距/颜色/边框规则，操作与状态图标，材料与功法图标，提示、进度和空状态 | 成长、行动、维护授权各有清楚层级；图像不能代替成功率、材料消耗等必要说明 | 1：信息与令牌规则；6：确认素材核验后覆盖各界面 |
| 品牌 | 骑士头部共用图标、旧程序图标与标题 | 产品标识、托盘及窗口图标、启动与关于页最小规范 | 产品名沿现有《桌面修仙传》设计基线；标识不直接裁一张复杂立绘，须小图专门简化 | 7：角色与色彩稳定后制作，终验所有入口 |

各类别都需维护“原画—分件/状态—实际尺寸预览—来源与确认记录”的关系。妖物、建筑等都应遵循已确认方向和后续主角确认稿，避免各自形成互不一致的体系。

## 七、玩法保持与接入原则

本方案不改变凡人主动战斗、十次有效击杀后的觉醒、炼气成长、筑基契机与突破结算、自动作战解锁、力竭调息、洞天生产或存档迁移规则。境界层数、收益、材料消耗、成功率和持续时长，以当前游戏逻辑为准。

美术可以让“调息”更符合修仙语义，但不能增加恢复收益或改变恢复时刻；可以把升级提示统一为合适的中文反馈，但不能把战斗熟练等级升级误称为修仙突破。真实维护授权与游戏反馈继续分别显示，图像不能暗示击败妖物必然清理了真实文件。

当前分件、骨骼坐标、朝向镜像和状态路由存在明确约束。新头身比、独立法衣下摆、独立灵气层、境界驱动换装与调息动作，都可能需要后续代码适配。制作文档先声明需求，接入阶段再分别验证；不得承诺只替换 PNG 就能得到全部新表现。
