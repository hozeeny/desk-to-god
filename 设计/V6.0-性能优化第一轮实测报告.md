# 《桌面修仙传》V6.0｜性能优化第一轮实测报告（P0 帧量化 + P1 自适应节拍）

测量日期：2026-10-17 ｜ 分支：feature/v6-dongtian（PR #5）
优化前基线：dfa6873（洞天存档闭环提交，渲染未动）
优化后：本提交（AdventureController.cs / AdventureModel.cs）
测量工具：`骑士助手.exe --perf-probe 2`（忙碌战场 120s ＋ 静止清场 30s 双段报表）

## 一、优化内容

- **P0 动画帧量化 + 脏标记跳绘**：主角与妖物按签名（动画帧序号、相位、朝向、血量档位、特效档位、标签等）判脏，签名不变跳过 PaintWindow 仅更新窗口位置；妖物完全静止（无受击/攻击闪光/未被拖拽/非新窗口）时整体跳绘。战斗/跑动期量化 24 档，静止期 12 档。
- **P1 自适应节拍**：演示、拖拽、攻击动画、实际移动、拾取、黑洞特效、任一可见敌处于战斗态时保持 15ms 节拍；完全平静时降至 33ms。隐藏桌宠原有的 enabled=false 零渲染路径保持不变。
- **探针增强**：新增进程资源快照（CPU/工作集/私有内存/句柄/GDI/USER）、栅格化帧计数、静止段场景（停战清场 30 秒）。
- **未做**：P2 索敌降频、P3 渲染分配修整（本轮跳过，见其后的"未做项"）；渲染后端替换（Direct2D/Skia）未触碰。

## 三、静止场景（停战清场 30s，优化后探针新增段落）

| 指标 | 优化后实测 | 优化前 |
|---|---|---|
| 进程 CPU | 3.2 s / 30.0 s ＝ **10.6% 单核** | 无实测（旧探针无静止段） |
| 节拍 | 33ms 自适应节拍生效（635 拍 / 30s） | 固定 15ms |
| tick-total 每拍均耗 | 5.1 ms | 解析推算约 5–11 ms（主角全量重绘为主） |
| 栅格化帧数 | 588 帧 / 635 拍（≈20fps，几乎全为主角呼吸重绘） | 约 66fps 意图全量重绘 |
| GDI / USER 对象 | 38 / 32（较忙碌段回落，无滞留增长） | — |

**静止段推算说明（非实测）**：若旧代码在静止场景仍以 15ms 节拍每拍全量重绘主角（约 5–11ms/拍），静止 CPU 占用估算在 33%–70%+ 单核区间。此数值为解析推算，非测量值，仅供参考量级。

## 四、结论（诚实口径）

1. **忙碌战场是最差场景**（全员持续战斗动画，签名几乎必然每拍变化），提升有限：CPU −13%、整拍 −26%。不宣称达到问题卡中"−60~80%"的预期上限——该预期针对的是静止/低活动场景。
2. **静止场景是桌宠的常态**，优化后实测降至 10.6% 单核，且剩余开销几乎全部来自主角 12 档呼吸重绘（≈20fps 栅格化），属设计保留的观感底线；进一步降帧或深度静止再降频是下一轮候选。
3. 优化后报表中忙碌段"节拍 33ms"为收尾瞬间读数；战斗中实际在 15/33ms 间按战斗态振荡，属预期行为。
4. 平静期主角仍按量化呼吸节奏重绘（约每拍 0.93 帧），是设计如此，非漏判脏。
5. 测量期间 PR #1 长测并存，与基线测量条件一致；两组数据均不代表无负载空闲机器。
6. GDI/USER 对象在忙碌→静止回落（80/60 → 38/32），短程无泄漏迹象；长期趋势以 PR #1 长测为准。
